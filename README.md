# الهرم للاتصالات والصيانة

نسخة محسّنة من التطبيق الحالي، مع الاحتفاظ ببيانات Firebase وبنية مجموعاته. لم تُعدّل السجلات المالية. أثناء المزامنة حُفظت نسخة من قواعد الإنتاج السابقة، وأُضيف سجل تفعيل لحساب قديم للحفاظ على وصوله الموجود.

## التشغيل

شغّل من مجلد المشروع:

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

ثم افتح `http://127.0.0.1:8080`. يلزم تقديم الملفات عبر HTTP/HTTPS لأن التطبيق يستخدم JavaScript Modules. يتطلب تحميل Firebase والخطوط والبيانات اتصالاً بالإنترنت؛ هذه النسخة لا تدّعي توفير العمل الكامل دون اتصال.

## ملفات النشر

ارفع الملفات التالية مع الحفاظ على المسارات:

- `index.html`
- `app.js`
- `app-core.mjs`
- `styles.css`
- `manifest.json`
- مجلد `assets`
- `CNAME` و`.nojekyll`
- `icon-192.png` و`icon-512.png`

تحتوي `release/alhram-improved.zip` على هذه الملفات فقط. لا ترفع النسخة الأصلية أو الاختبارات أو مسودات القوالب ضمن موقع الإنتاج.

## التغييرات

- فصل JavaScript وCSS والصورة الأصلية عن HTML، وإعادة استخدام الصورة بدلاً من تكرار Base64.
- نسخ عميق عند قراءة الذاكرة؛ إصلاح التعديلات التي لم تكن تُحفظ، مع استرجاع التغييرات المتفائلة عند رفض الحفظ.
- تجميع الكتابات المتزامنة المرتبطة في دفعة Firestore ذرية، وتأخير إشعارات النجاح حتى اكتمالها.
- تسديد الدين وتعديل الدفعة داخل معاملة تقرأ القيم الحالية من الخادم وتحدّث الدين والدفعة والصندوق والصيانة معًا.
- منع الدفعات السالبة وغير المحدودة والزائدة، ومنع التكرار أثناء حفظ النماذج الأساسية.
- ربط المصروف بمعاملته عبر `cashId`. المصروفات القديمة التي يتعذر تحديد معاملتها بدقة تتطلب مراجعة بدلاً من تعديل معاملة محتملة بالخطأ.
- حفظ السجلات القديمة المرتبطة عند تغيير اسم العميل. لم يتم فرض ترحيل شامل إلى معرّفات عملاء جديدة على البيانات الفعلية.
- إصلاح حذف الصيانة ليشمل معاملات دفعات ديونها؛ منع التعديل المستقل في الصندوق للسجلات المرتبطة بالأقسام الأخرى.
- نسخ احتياطي بإصدار 2 يشمل المجموعات العشر والإعدادات، وفحص للملف ومعاينة قبل الاستبدال. النسخ القديمة لا تمسح الأقسام التي لم تتضمنها.
- رفض الاستيراد أو المسح الذي يتطلب أكثر من 450 كتابة قبل تنفيذ أي جزء منه؛ النسخ الكبيرة تحتاج أداة استيراد إدارية.
- كلمات الحذف الجديدة تُحفظ كمشتق PBKDF2 مع ملح عشوائي. كلمة الحذف القديمة تُرقّى عند حفظ الإعدادات أو التحقق الصحيح منها. لا تُضمّن بيانات حماية الحذف في النسخة الاحتياطية؛ الاستيراد يحافظ على حماية الحساب الحالي.
- استبدال كلمة الأرباح الثابتة بإعادة التحقق من كلمة مرور الحساب عبر Firebase Authentication.
- إيقاف ترحيل بيانات الجذر التلقائي إلى كل حساب يسجل الدخول.
- حماية حقول نصية ومعاملات أزرار ديناميكية من تفسيرها كـHTML أو JavaScript.
- مؤشر للحفظ والاتصال، وتحسين التركيز المرئي والحقول والجوال وتقليل الحركة، مع تمييز صافي حركة البنك عن الصندوق.
- إصلاح وسوم HTML غير المغلقة التي كانت تُدخل المحتوى والنوافذ داخل الترويسة، وإزالة بطاقة إعدادات مكررة.
- أرشفة نوافذ المبيعات غير المكتملة الأصلية في `templates/sales-draft.html` بدلاً من تحميل أزرار تستدعي دوال غير موجودة.

## التحقق

يلزم Node.js يدعم `node:test` وVM Modules:

```powershell
node --experimental-vm-modules --no-warnings --test tests/app.test.mjs
python tests/check_markup.py
```

تستخدم الاختبارات قاعدة بيانات وDOM معزولين في الذاكرة، وتشمل الحفظ والفشل والدفعات والنسخ والاستيراد وربط المعاملات. لا تتصل اختبارات التطبيق بقاعدة الإنتاج. اختبارات القواعد الإضافية تستخدم المحاكي. يلزم التحقق من الواجهات التفاعلية والطباعة والجوال بحساب تجريبي؛ لم تُستخدم بيانات دخول المستخدم في اختبارات مالية فعلية.

## Firebase وGitHub Pages

الموقع مستضاف في مستودع `mohammedsoft7-creator/alharam-service` على الدومين `alhram.online`. بقي `CNAME` محفوظاً، ومسارات التطبيق وملف التثبيت نسبية لتعمل على الدومين أو مسار GitHub Pages. نشر Firebase يقتصر على قواعد Firestore، ولا ينقل استضافة الموقع إلى Firebase Hosting.

تحتوي `firestore.rules` على عزل بيانات الحسابات النشطة، وتثبيت هوية المالك بمعرّف Firebase Auth المتحقق منه، ومنع إنشاء سجل تفعيل ذاتي دون استهلاك كود غير مستخدم داخل العملية الذرية نفسها. لا يمكن تعداد الأكواد إلا للمالك، والحساب المعطّل لا يستطيع إعادة تفعيل نفسه. الحسابات القائمة محفوظة، مع ترحيل سجل تفعيل لحساب قديم كان يملك بيانات بالفعل.

تسجّل الواجهة حساب Firebase Authentication أولاً، ثم تنفّذ معاملة تربط كود التفعيل بسجل الحساب وإعداداته. يمكن استكمال التسجيل المنقطع بنفس البريد وكلمة المرور وكود صالح. لا تمنع قواعد Firestore إنشاء هوية Auth غير مفعلة؛ تمنع وصولها إلى بيانات التطبيق حتى اكتمال التفعيل. لا توجد أدوار موظفين منفصلة داخل المحل في هذه النسخة.

شُغّلت 13 حالة اختبار على محاكي Firestore بمشروع تجريبي `demo-alhram-rules`، إضافة إلى 29 اختبار تطبيق وفحص بنية HTML. لا تنشئ الاختبارات حسابات أو سجلات مالية في الإنتاج. يمكن إعادة تشغيلها بعد تثبيت Node.js وJava 21:

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run test:rules
```

ينفّذ GitHub Actions الفحوص عند تحديث `main` وطلبات السحب. لا يحتوي سير الفحوص أي مفاتيح أو صلاحية لنشر Firebase. لتحديث القواعد لاحقاً بعد اختبارها وتسجيل الدخول بالحساب الصحيح:

```powershell
npm run deploy:rules -- --account mohammed.soft7@gmail.com
```

نسخة القواعد السابقة موجودة محلياً في `backups/firebase`، وتقارير النشر والمزامنة الخاصة في `deployment-private`. هذه المجلدات وجلسات الدخول والأدوات المحلية مستبعدة من Git والنشر.

حُفظت معاني الحقول المالية القديمة، بما فيها `total`، لتجنب تغيير نتائج السجلات القائمة دون ترحيل محسوب. بقي فصل حساب الربح عن المقبوضات وربط كل العمليات بمعرّفات عملاء ثابتة كتطوير لاحق يحتاج مراجعة البيانات.

النسخة الأصلية متاحة محليًا في `backups/index.before-improvements.html` للرجوع إليها.
